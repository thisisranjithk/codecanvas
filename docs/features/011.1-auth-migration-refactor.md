# Feature 011.1 - Authentication Session Lifecycle Refactor

## Objective

Refactor the frontend authentication flow into a production-ready session management architecture.

The current implementation has lifecycle issues where authentication initialization, login, logout, and session restoration are not clearly separated.

The goal is to create a predictable authentication lifecycle that avoids unnecessary API requests, prevents accidental logout on page refresh, and keeps the codebase clean and maintainable.

---

# Context

The backend authentication is already complete.

Authentication uses

* Access Token (returned by Login & Refresh APIs)
* HttpOnly Refresh Cookie
* Refresh Token Rotation

Do not modify the backend.

Only refactor the frontend authentication flow.

---

# Existing Problems

Current implementation has the following issues.

### Problem 1

The Login page unnecessarily triggers

GET /auth/me

and

POST /auth/refresh

before authentication.

Public routes should never initialize authenticated sessions.

---

### Problem 2

Refreshing the browser logs the user out.

The application should restore the authenticated session automatically using the Refresh Token Cookie.

---

### Problem 3

Authentication responsibilities are spread across multiple places.

Session initialization

Axios

Auth Context

Route Guards

Hooks

all partially manage authentication.

There should be a single source of truth.

---

# Goal

Create a production-grade authentication architecture.

Authentication should have one clearly defined lifecycle.

Authentication should initialize only once.

Authentication should restore sessions automatically.

Public pages should never perform authenticated initialization.

---

# Architecture

Authentication should be divided into four responsibilities.

## 1. Session Manager

Responsible for

* Session initialization
* Session restoration
* Refresh lifecycle
* Access Token storage

Nothing else should restore sessions.

---

## 2. Auth Context

Responsible only for

* Current user
* Authentication state
* login()
* logout()
* loading

Auth Context should not contain API logic.

---

## 3. Axios Client

Responsible only for

* Authorization header
* Automatic token refresh
* Retry failed requests

Axios should never navigate.

Axios should never update UI state.

---

## 4. Route Guards

Responsible only for

* Public routes
* Protected routes

Nothing else.

---

# Authentication Lifecycle

The authentication lifecycle should be predictable.

---

## Application Startup

Application Starts

↓

Check current route

↓

If current route is Public

↓

Skip authentication initialization

↓

Render page

---

If current route is Protected

↓

Attempt session restoration

↓

POST /auth/refresh

↓

Success

↓

Store Access Token in memory

↓

GET /auth/me

↓

Update Auth Context

↓

Render protected application

↓

Failure

↓

Redirect Login

---

# Login Flow

Login Page

↓

POST /auth/login

↓

Receive Access Token

↓

Browser stores Refresh Cookie automatically

↓

Store Access Token in memory

↓

GET /auth/me

↓

Update Auth Context

↓

Navigate Dashboard

Do not call Refresh after Login.

Do not restore session after Login.

The session already exists.

---

# Page Refresh

User presses F5

↓

Application Starts

↓

Protected Route

↓

POST /auth/refresh

↓

Receive New Access Token

↓

Store Access Token in memory

↓

GET /auth/me

↓

Restore User

↓

Continue Application

User should never notice this process.

---

# Public Routes

Examples

* Login
* Register

These pages should

NOT call

GET /auth/me

NOT call

POST /auth/refresh

NOT initialize authentication

Simply render normally.

---

# Protected Routes

Protected pages should wait until authentication initialization completes.

Flow

Protected Route

↓

Authentication Loading

↓

Session Restore

↓

Authenticated

↓

Render Page

Otherwise

↓

Redirect Login

Never render protected content before authentication finishes.

---

# Session Initialization

Authentication initialization should happen exactly once.

Never initialize authentication

inside

* Login Page
* Register Page
* Feature Hooks
* Individual Pages

Create one centralized session initialization mechanism.

---

# Token Refresh

Axios interceptor should

Only refresh when

* Access Token expired
* Server returns 401

Flow

401

↓

POST /auth/refresh

↓

Receive New Access Token

↓

Retry Original Request

↓

Continue

Retry only once.

Prevent infinite loops.

---

# Logout

Logout Flow

POST /auth/logout

↓

Clear Memory Token

↓

Clear Auth Context

↓

Clear React Query Cache

↓

Redirect Login

---

# Session Restoration

Session restoration should occur

ONLY

during

Application Startup

OR

401 Token Refresh

Nowhere else.

---
